# ADR-0008：任务标识采用 GTID（General Task Identifier）

| 状态 | 日期 | 决策者 |
|------|------|--------|
| 已采纳 | 2026-05-29 | 韵启龙 |

---

## 背景

系统中有三类需要统一标识的事物：

1. **用户发起的交互**（如 AI 对话）
2. **系统发起的业务 Task**（如周期性采集传感器数据）
3. **系统发起的运维 Task**（如看门狗、负载均衡、热备切换）

它们都需要一个统一的 ID 系统：跨层携带、可暂停/调频/查历史、不与任何单一层强绑定。

## 决策

采用 **GTID（General Task Identifier）** 作为统一标识。

- **General**：覆盖上述三类 Task，不分发起方是谁
- 16-bit 无符号整数，三级划分：

```
15        12  11        6  5        0
┌────────────┬───────────┬───────────┐
│  Category  │ TaskType  │   Index   │
│  (4 bits)  │ (6 bits)  │ (6 bits)  │
└────────────┴───────────┴───────────┘
```

| 字段 | 位宽 | 含义 |
|------|------|------|
| Category | 4 | Task 分类：系统自发 / 用户发起 / 业务触发 |
| TaskType | 6 | 同类下具体业务类型，最多 64 种 |
| Index | 6 | 该类型下的任务编号，最多 64 个并发 |

**Category 分区**：

| Category 值 | 名称 | 说明 |
|-------------|------|------|
| `0x0` | **System** | 系统自身运维 Task（看门狗、负载均衡、热备等） |
| `0x7` | **User** | 用户发起的 Task（AI 对话等） |
| `0xC` | **Other** | 系统发起的业务 Task（轮询传感器、定时采集等） |
| 其余 | 保留 | 留备扩展 |

每个 Category 内按 TaskType 进一步划分。暂只启用以下范围，其余留备扩展：

| GTID 范围 | Category | TaskType | 说明 |
|-----------|----------|----------|------|
| `0x0000` | — | — | 空值 |
| `0x0001` ~ `0x0FFF` | System (0x0) | 0x00 ~ 0x3F | 系统自身运维 Task |
| `0x1000` ~ `0x1FFF` | System 扩展 | — | 保留 |
| `0x2000` ~ `0x6FFF` | — | — | 保留 |
| `0x7000` ~ `0x7FFF` | User (0x7) | 0x00 ~ 0x3F | 用户发起的 Task |
| `0x8000` ~ `0x8FFF` | User 扩展 | — | 保留 |
| `0x9000` ~ `0xAFFF` | — | — | 保留 |
| `0xB000` ~ `0xBFFF` | Other 扩展 | — | 保留 |
| `0xC000` ~ `0xCFFF` | Other (0xC) | 0x00 ~ 0x3F | 系统发起的业务 Task |
| `0xD000` ~ `0xFFFE` | — | — | 保留 |
| `0xFFFF` | — | — | 广播/通配 |

**提取方式**：

```cpp
auto cat      = gtid >> 12;         // Category (4 bits)
auto taskType = (gtid >> 6) & 0x3F; // TaskType (6 bits)
auto idx      = gtid & 0x3F;        // Index    (6 bits)
```


- 代码中用 `gtid`，文档中用 GTID
- 生命周期：Task 建立时分配，结束后回收
- Category、TaskType、Index 三级划分，各 6 位 TaskType 和 Index 子域

## 备选方案

| 方案 | 全称 | 否决原因 |
|------|------|----------|
| `sessionId` | Session Identifier | 与 Session Layer 命名重叠；"会话"暗示人-系统交互，不覆盖系统自发 Task |
| SID | Scope Identifier | "Scope"含义模糊，中文无法准确对应 |
| FTI | Flow Temporary Identifier | "Flow"指单次消息流转，太细；"Temporary"不适用 |
| CTID | ConText IDentifier | 与已有 Context 类型名混淆 |
| TID | Task Identifier | 过于通用，与操作系统调度术语冲突 |

## 参照设计

5G RNTI（Radio Network Temporary Identifier）的设计思路——短整数、范围分区、由高层分配。GTID 借鉴其范围分区思路。

## 影响

- 所有消息体需携带 `gtid` 字段（16-bit）
- SessionMgr 负责 GTID 的分配与回收
- ServiceMgr 创建系统 Task 时从 System GTID 范围内申请
- README 中相关描述统一改为 GTID
